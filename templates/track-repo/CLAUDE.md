# {{SONG}}

Track repo. Song content only: this song's documents, parts and mix chain. **Private, and
it stays private.**

The tooling lives in a separate repo, the scaffold, at `{{SCAFFOLD}}`. It is also reachable
from here as `.claude/scaffold`. Its `CLAUDE.md` carries the method these agents work
under. Read it when a question is about how to work rather than about this song.

The agents and slash commands in `.claude/` are symlinks into the scaffold, so editing one
there changes it everywhere. They are gitignored; after cloning this repo on another
machine, run `<scaffold>/bin/new-song {{SONG}} --relink`.

---

## Read before anything

1. `brief.md` — what the song is, and which choices are deliberate
2. `structure.md` — section map, start beats, tempo, key
3. `log.md` — what happened last session and what is open
4. `harmony.md` and `lyrics.md` when the session touches those

Do not skip `brief.md`. It is what separates a deliberate choice from a mistake, and its
"Deliberate choices that look like mistakes" section exists so nothing here gets
"corrected" that was meant.

---

## Critical conventions

**C3 = MIDI 60.** When a note name and a MIDI number disagree, the MIDI number wins.

**Arrangement view, not Session view.** AbletonMCP writes to Session clips only, so draft
there and drag to the Arrangement. The bridge scripts talk to AbletonOSC, which is
arrangement-aware.

**The Ableton session is source of truth.** `parts/` and `chain/` are `/pull` output, a
cache, gitignored and rebuildable. Documentation is a claim about the session, and claims
get checked.

**No em-dashes. No AI-speak. No therapy-speak.** Plugin parameters in real UI units, with
meter mode and swing-vs-resting stated.

## Files here

| File | What |
|---|---|
| `brief.md` | Backstory, artistic principles, production rules, deliberate oddities |
| `structure.md` | Section map with start beats, bars, times |
| `harmony.md` | Pitch reference table, chord map, closed harmonic questions |
| `lyrics.md` | Canonical lyrics, tagged by section |
| `log.md` | Decisions and reasoning, append-only, newest last |
| `conflicts.md` | Discrepancies needing the session open to resolve |
| `midi-patterns.md` | Hand-written note-level part documentation, and the drum map in use |
| `returns.md` | Return track inventory |
| `files.md` | Where the Ableton project, MIDI and stems actually are |
| `parts/` | Generated by `/pull`, one file per arrangement clip |
| `chain/` | Generated, one file per track, device list and parameters |
| `mix/` | Spectrograph captures plus `readings.md` |

## Agents

| Agent | Use for |
|---|---|
| `orchestrator` | Sessions spanning several domains, or a full section review |
| `structure` | Bar map, section edits, cue points, transitions |
| `harmony` | Chord map, voice-leading, melodic and vocal parts |
| `rhythm` | Drum programming, groove, percussive texture |
| `mix-chain` | Device parameters, mix decisions, spectrograph reads |

## Commands

| Command | What it does |
|---|---|
| `/pull` | Sync the Ableton arrangement into `parts/` and `chain/` |
| `/push <part-file>` | Write notes from a part file into an Ableton Session clip |
| `/device <track> <device> <param> [value]` | Read or set a device parameter by name |
| `/log <message>` | Append a dated decision entry to `log.md` |

Run the bridge directly when you need flags the commands do not expose:

```bash
export ABLETON_SONGS_DIR=<the folder containing this repo>
python3 .claude/scaffold/bridge/pull.py --song {{SONG}}
python3 .claude/scaffold/bridge/device.py --track "<Track>" --snapshot --song {{SONG}}
```

## Ending a session

Append a `/log` entry: what changed, what was decided, what is still open. Flag anything
newly contradictory into `conflicts.md`. A session that ends without a log entry has to be
reconstructed from memory next time, and that is where documentation drift starts.
